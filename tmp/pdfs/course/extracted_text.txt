You have already read chapters 2 and 3 of Deep Learning with Python, third edition. This course revisits their code
with a different question: what is Python doing at each step? The goal is to make you comfortable reading, changing,
debugging, and writing that code yourself.
The source is the two third-edition companion notebooks in the main folder of your repository. The first_edition
and second_edition folders were not used. This is an original teaching companion, not a reproduction of the book's
prose. It covers the Python constructs that occur in these two notebooks, plus a few small extensions needed for
practice. It does not claim to cover the entire Python language.
Each source locator gives a notebook chapter, a heading, and a zero-based cell index, counting both Markdown and
code cells. For example, chapter 2 cell 6 is the seventh cell in the file. These are file positions, not the changing
execution numbers shown beside notebook cells. Repeated code is explained once and connected to its later uses.
Read code actively. Before running a block, predict its result and the type and shape of each important value. Then
run it. Change one thing, predict again, and explain the result in your own words. Typing a small example from
memory is more useful than copying an entire training loop.
Example labels. Exact excerpts retain the source's logic. Adaptations use smaller inputs, clearer names, or explicit
corrections. A block described as a continuation needs the objects defined immediately before it. Framework
examples require the named framework; tiny Python and NumPy examples are the easiest place to begin.

2. The execution environment is part of the lesson
Source: both notebooks, setup cells 1-3; repository README, choosing a backend.
A notebook is a collection of cells sharing one running Python process, called a kernel. Variables survive between cell
executions. If you execute a cell twice, it acts on the state left by the first execution. If you change an earlier function
definition, later calls use the most recently executed definition.
The display order on screen is not proof of execution order. NameError often means the defining cell has not run. A
mysterious wrong shape can mean a previous cell already reshaped the array. In chapter 2, train_images is initially
three-dimensional, becomes two-dimensional after preprocessing, and later returns to three dimensions when
MNIST is loaded again.
Use a fresh notebook for your exercises. For the original framework examples, use the environments described by
the repository README. A useful check inside any notebook is:
PYTHON
import sys
print(sys.executable)
print(sys.version)
This tells you which Python process is actually running. Installing a package in one environment does not make it
available to a notebook using a different environment.
Python syntax versus notebook syntax
OUTPUT / NOTEBOOK
!pip install keras keras-hub --upgrade -q
%%backend tensorflow
# @title
! asks IPython to run a shell command. It is not valid syntax in an ordinary .py file. The first line asks pip to install
packages; --upgrade and -q are command-line options, not Python operators. %%backend is a custom cell magic
registered by the notebook's helper. It is also not ordinary Python. The # @title line is a Python comment with
additional meaning to Colab's interface. These setup conveniences are separate from the language you are learning.
The notebook package name keras-hub and Python import names are also different kinds of name. A hyphen is
allowed in a package distribution name; in Python code, keras-hub would mean subtraction. You do not need
KerasHub features for the core examples taught here.
Selecting the Keras backend
PYTHON
import os
os.environ["KERAS_BACKEND"] = "tensorflow"
import keras
os is a standard-library module. os.environ is a mapping of environment variable names to string values. The square
brackets select a key; assignment stores the string "tensorflow" for that key. This configuration must happen before
importing Keras in a fresh process. Changing the string after Keras has initialized does not switch the already-running
backend. Restart the kernel when switching.
The local chapter 2 notebook selects TensorFlow; chapter 3 initially selects JAX. Importing tensorflow directly and
selecting TensorFlow as Keras's backend are related but separate actions. The examples in chapter 3 also use each
framework directly.

3. Names, values, types, and punctuation
Source: chapter 2, first example, cells 6-21; small examples below are teaching adaptations.
PYTHON
epochs = 5
learning_rate = 1e-3
activation_name = "relu"
use_bias = True
activation = None
= binds a name to a value. The values above have types int, float, str, bool, and NoneType. 1e-3 means 0.001; it is
one floating-point literal. None is the single Python object used to represent absence, such as an optional activation
that was not provided. It is not the string "None", zero, or an empty list.
Names are case-sensitive: W and w can refer to different objects. Underscores connect words in names such as
train_images. Python does not require you to declare a variable's type, and a name can later be rebound to a
different type. That freedom is useful, but reusing model for several unrelated functions and objects can make a long
notebook harder to understand.
PYTHON
pixels = 28 * 28
print(pixels, type(pixels))
print(5 / 2, 5 // 2, 5 % 2, 2 ** 3)
The first line computes 784 before assigning it. The second print displays values equivalent to 2.5 2 1 8: true
division, floor division, remainder, and exponentiation. // is introduced here for practice; the source batch class uses
math.ceil instead. Multiplication and division bind more tightly than addition and subtraction. Parentheses make
grouping explicit: 128 * (n + 1) differs from 128 * n + 1.

Lists, tuples, and dictionaries
PYTHON
units = [512, 10]
shape = (28, 28)
one_axis = (10,)
history = {"loss": [0.8, 0.4, 0.2]}
print(units[0], shape[-1], history["loss"][-1])
The output is 512 28 0.2. Lists and tuples preserve order. Indexing starts at zero; -1 selects the last item. Lists can
have their contents changed, while a tuple's item references cannot be reassigned. The comma makes a
one-element tuple: (10,) is a tuple, but (10) is just the integer 10 surrounded by grouping parentheses. An empty
tuple is (); it represents a scalar array's shape later in the course.
A dictionary maps keys to values. Here the key is the string "loss" and its value is a list. Reading
history["loss"][-1] means first retrieve that list, then retrieve its final item. A missing dictionary key raises
KeyError. In history.history, the first history in the chapter 3 notebook is an object name, while the second is its
attribute, which contains a dictionary.
Names point to objects
PYTHON
first = [1, 2]
second = first
second[0] = 99
print(first)              # [99, 2]
second = [7, 8]
print(first)              # [99, 2]
The assignment second = first does not copy a list. Both names initially refer to the same object, so changing an
item through either name affects that object. Later, second = [7, 8] binds the name to a different object. It does
not replace the object still referred to by first. This distinction explains much of the chapter 3 difference between
rebinding a Python name and updating a framework variable.
An array's Python type and element dtype answer different questions. type(x) might be numpy.ndarray; x.dtype
might be float32. The first describes the container object. The second describes how numerical elements are
represented.
4. Imports, attributes, calls, and unpacking
PYTHON
import numpy as np
from keras import layers
from keras.datasets import mnist
import numpy as np imports a module and binds it to the local alias np. as does not change the library itself. from
keras import layers brings a selected name into the current namespace; it does not create the separate name
keras. If you later write keras.Sequential, you still need import keras.

Dots navigate attributes: keras.datasets.mnist names something inside something else. In x.shape, the attribute
already holds a value, so you do not call it. In x.reshape(...), the attribute is a method that you call. In
np.reshape(x, ...), a function in a module receives x explicitly. The API determines which form exists.
Trace a call from inside to outside
PYTHON
import numpy as np
x = np.zeros((2, 3), dtype="float32")
print(x.shape)
First Python looks up zeros on the module np. It then evaluates the arguments from left to right, building the tuple
(2, 3) and the string "float32", and calls the function. (2, 3) is a positional argument: its location identifies the
parameter. dtype="float32" is a keyword argument: its name identifies the parameter. The resulting array is bound
to x. Finally, print receives x.shape, displaying (2, 3).
The = in dtype="float32" supplies a named argument. It does not create a variable named dtype in your
surrounding scope. Ordinary positional arguments come before keyword arguments. A parameter is a name in a
function definition; an argument is the actual value supplied in a call.
Unpack the data structure, not just the words
Exact source pattern, chapter 2 cell 6:
PYTHON
(train_images, train_labels), (test_images, test_labels) = (
    mnist.load_data()
)
mnist.load_data() returns a pair, and each element of that pair is another pair. Python matches the structure on
the left to the returned structure on the right. It assigns the four contained arrays to four names. Parentheses
around the right side merely let the expression continue across lines.
This tiny stand-alone example has the same structure:
PYTHON
(train_x, train_y), (test_x, test_y) = (("A", "B"), ("C", "D"))
print(train_x, train_y, test_x, test_y)
It prints A B C D. A mismatched number of values raises ValueError; unpacking does not guess which value belongs
to which name. test_loss, test_acc = model.evaluate(...) is the same idea with one level of nesting. The
number of returned results depends on the configured metrics.

5. Read the first neural network as a Python program
Source: chapter 2, "A first look at a neural network", cells 13-21. The blocks below retain the source's model and data flow, with extra
explanatory comments. They require Keras, a selected backend, and the MNIST data loaded in the preceding section. A first dataset
load may download MNIST.
PYTHON
import keras
from keras import layers
model = keras.Sequential(
    [
        layers.Dense(512, activation="relu"),
        layers.Dense(10, activation="softmax"),
    ]
)
Read from the inside outward. Calling layers.Dense constructs one layer object. Calling it again constructs a second
object. Square brackets put the two objects into a list, in order. keras.Sequential receives that list and constructs a
model object. The name model then refers to that object.
The strings "relu" and "softmax" are values the built-in layer knows how to interpret. Python itself has no special
activation syntax. A custom class must explicitly implement any string-to-function conversion it needs; this matters

11. Classes make state and behavior travel together
Notebook locator: "A simple Dense class," cell 96; "A simple Sequential class," cells 98-99.
class NaiveDense: defines a new Python class. Calling NaiveDense(...) creates an instance and initializes it
through __init__. Python supplies the instance as the first method argument, conventionally named self. self.W
belongs to that instance; an ordinary local variable such as x exists only in the method call. Two layer instances

The following is a teaching adaptation of cell 96, compressed without changing its structure. Dependencies: Keras

PYTHON
class NaiveDense:
    def __init__(self, input_size, output_size, activation=None):
        self.activation = activation
        self.W = keras.Variable(
            shape=(input_size, output_size), initializer="uniform"
        )
        self.b = keras.Variable(shape=(output_size,), initializer="zeros")
    def __call__(self, inputs):
        x = ops.matmul(inputs, self.W) + self.b
        if self.activation is not None:
            x = self.activation(x)
        return x
    @property
    def weights(self):
        return [self.W, self.b]
The initializer strings tell Keras how to create numerical weights. Python handles argument passing and attribute
assignment; Keras supplies numerical storage and trainable variables. (output_size,) is again a one-element shape
tuple. None is a special singleton used here to mean "no activation." is not None checks identity against that
singleton and is the normal Python idiom.
activation=ops.relu passes the function object so the layer can call it later. activation=ops.relu(x) would call it
immediately and pass the result instead. The expression self.activation(x) is the later invocation. Functions are
values: you can store them in variables, pass them as arguments, and retain them in attributes.
Defining __call__ makes an instance callable. After layer = NaiveDense(3, 2), layer(inputs) invokes its
__call__ method. Construction and prediction are different calls: NaiveDense(...) initializes state; layer(...)
uses that state. For inputs shaped (5, 3), the matrix multiplication produces (5, 2), and the bias of shape (2,)
broadcasts across five examples.

layer.weights, without parentheses; reading it executes the getter and returns a newly created Python list
containing references to the two variables. The variables themselves are not copied. layer.weights() would try to
call the returned list and fail.

class NaiveSequential:

    def __call__(self, inputs):

class BatchGenerator:
    def __init__(self, images, labels, batch_size=128):

        self.images = images
        self.labels = labels

class Batches:
    def __init__(self, images, labels, size=4):

        self.images, self.labels = images, labels
        self.size, self.index = size, 0

        return self
    def __next__(self):
        if self.index >= len(self.images):

        start = self.index
        self.index += self.size
        return (self.images[start:self.index],

import keras
from keras import ops
learning_rate = 1e-3
def update_weights(gradients, weights):
    for g, w in zip(gradients, weights):
        w.assign(w - g * learning_rate)
def one_training_step(model, images_batch, labels_batch):
    with tf.GradientTape() as tape:
        predictions = model(images_batch)
        losses = ops.sparse_categorical_crossentropy(
            labels_batch, predictions
        )
        average_loss = ops.mean(losses)
    gradients = tape.gradient(average_loss, model.weights)
    update_weights(gradients, model.weights)

20. with ... as ... controls a region of execution

21. A complete TensorFlow step, read as Python
Source: linear-classifier cells 38-42. Dependencies: TensorFlow and the NumPy inputs and targets from section 17. The following

PYTHON

def linear_tf(inputs, W, b):
    return tf.matmul(inputs, W) + b
def mse_tf(targets, predictions):
    return tf.reduce_mean(tf.square(targets - predictions))

def step_tf(inputs, targets, W, b):
    with tf.GradientTape() as tape:
        predictions = linear_tf(inputs, W, b)
        loss = mse_tf(targets, predictions)
    grad_W, grad_b = tape.gradient(loss, [W, b])
    W.assign_sub(learning_rate * grad_W)
    b.assign_sub(learning_rate * grad_b)
    return loss

    loss = step_tf(inputs, targets, W, b)
    print(f"Step {step}: {float(loss):.4f}")

class SimpleDense(keras.Layer):

        super().__init__()

    def build(self, input_shape):

            initializer="random_normal",

just fixing exceptions. -1 in a reshape asks NumPy to infer that dimension from the number of elements.

import numpy as np
images = np.array([
    [[0, 255], [0, 255]],

    [[0, 128], [0, 128]],

Worked solution, step 2: a callable object
PYTHON
class TinyDense:
    def __init__(self, W, b):
        self.W = W.copy()
        self.b = b.copy()
    def __call__(self, inputs):
        return inputs @ self.W + self.b
    @property
    def weights(self):
        return [self.W, self.b]
W = np.array([
    [1, -1], [-1, 1], [1, -1], [-1, 1]
], dtype="float32")
b = np.zeros((2,), dtype="float32")
model = TinyDense(W, b)
assert len(model.weights) == 2
self refers to the instance being initialized or called. Copying the supplied arrays prevents later item changes to the
caller's arrays from silently changing this model. The property has no setter, but the arrays inside its returned list are
still mutable. A read-only property does not make the objects it exposes immutable.
features @ W multiplies a (5, 4) matrix by a (4, 2) matrix. Adding the (2,) bias broadcasts it over rows. Calling
model(features) invokes the instance's __call__ method and returns a (5, 2) score array.
Worked solution, step 3: slicing batches
PYTHON
def take_batch(features, labels, start, batch_size):
    if batch_size <= 0:
        raise ValueError("batch_size must be positive")
    stop = start + batch_size
    return features[start:stop], labels[start:stop]
batch_lengths = []
for start in range(0, len(features), 2):
    x_batch, y_batch = take_batch(features, labels, start, 2)
    scores = model(x_batch)
    batch_lengths.append(len(x_batch))
    assert scores.shape == (len(y_batch), 2)
assert batch_lengths == [2, 2, 1]
The three-argument range(start, stop, step) produces 0, 2, and 4. Slicing tolerates a stop beyond the end of an
array, so the last batch contains one example. A single return statement supplies a tuple of two slices, which the
caller unpacks. .append(...) mutates the existing list and returns None; avoid writing batch_lengths =
batch_lengths.append(...).
